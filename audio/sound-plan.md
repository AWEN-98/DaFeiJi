# 音频方向方案（Audio Direction）— P4-AUD

> 角色：audio-director ｜ 项目：融合 shmup + 肉鸽 + 合成 + 搜打撤 ｜ 平台：PC / Steam 首发 ｜ 美术：卡通渲染 ｜ 主题倾向：**中式志怪 / 都市奇幻**
> 本文档仅产出方案，不产出音频文件。事件 ID 为草案，供工程 / QA 对齐。

---

## 1. 音频整体方向

**一句话定位**：用「卡通渲染的明快音色」承载「中式志怪的诡谲气质」，让搜打撤的强风险博弈在声音上可被"听"出来。

| 维度 | 取向 | 说明 |
|---|---|---|
| 整体气质 | 轻快 × 诡谲 | 卡通基调保证易读、不刺耳；志怪主题提供记忆点（非遗感、留白、五声音阶） |
| 音色骨架 | 合成器为主 + 民族乐器点缀 | 合成器负责打击感/科技感（机体、弹幕）；竹笛/古筝/编钟/锣做"志怪"母题点缀，避免全程民乐导致氛围过重 |
| 节奏语法 | 网格化、可量化 | shmup 强节拍驱动，所有核心音效对齐 16 分音符网格，便于动态分层与心流 |
| 空间感 | 中近距、聚焦 | 弹幕密集，混音优先保证"你来我往"的清晰层次，避免混响淹没定位 |
| 情绪曲线 | 搜刮松弛 → 战斗紧绷 → 撤离悬疑 | 三段式情绪锚点贯穿单局，对应"低风险→高风险→胜负博弈" |

**主题呼应（若采用中式志怪 / 都市奇幻）**：
- 用**五声音阶（宫商角徵羽）**作为旋律基础，天然"中式"且不严肃。
- 志怪母题：用**失真古筝拨奏 / 金属锣的泛音**表现"妖异"，用**竹笛气声**表现"人间烟火"，形成都市（人造）vs 异界（志怪）的音色对立。
- Boss = 影视 IP 创作者（深耕山海经）：其主题乐可设计为"被剪辑/倒放"的民乐采样 + 工业噪声，暗示"创作者把神话变成了怪物"。

## 2. 战斗节奏音效方案

设计原则：**每个音效承担"读盘"功能**——玩家闭眼也能听出当前状态（开火 / 命中 / 受击 / 强化 / 合成 / 撤离）。每条给出设计意图与参考描述。

| 事件 | 设计意图 | 参考描述（音色 / 听感） |
|---|---|---|
| **开火** | 提供"射击手柄"反馈、统一节奏基准 | 短促方波 + 噪声瞬态，卡通"啾/嗒"感；不同机体用不同基频（高=轻机，低=重机）。带轻微音高下滑收尾 |
| **命中** | 确认"有效输出"，强化正反馈 | 高频"叮"金属音 + 短噪声爆点；命中大型敌/Boss 用更闷、更厚的版本以示权重 |
| **爆炸** | 爽点释放、清空屏压 | 低频 body（60–120Hz）冲击 + 宽带噪声撕裂 + 0.3s 尾噪；卡通化：加一点点"boing"弹性而非纯写实 |
| **受击** | 风险警示、打断心流 | 中频"噗/嗒"钝击 + 微失谐；血量越低音色越"干瘪/失真"，作为生理化预警 |
| **随机强化获得** | 肉鸽惊喜感 | "抽卡"上行琶音（五声音阶），伴随 glitch 闪光音；稀有度越高尾音越长越亮（普通/稀有/传说三级） |
| **合成成功** | merge 的正反馈闭环 | 两个素材音"咬合"→ 上扬和弦确认音；成功有清脆"咔嗒+铃"双段，失败（如有）用下沉闷响 |
| **撤离成功** | 风险落袋的释然 | 主题动机的"解决"版（五声终止式）+ 暖垫底；节奏松开，留呼吸感 |
| **撤离失败** | 损失沉没的打击 | 主题动机"悬而未决"截断 + 低频下沉 + 失真环境；刻意不做完整终止，留"未完成"的失落 |
| **UI 反馈** | 操作可读性 | 轻量 click（确认）/ 软"嗡"（取消）/ 滑动 whoosh（翻页）；全部在高频段，不与战斗音效抢频 |

## 3. 音乐基调与动态分层

**核心思路**：音乐不是背景，而是"战斗强度的仪表盘"。BPM 与战斗节奏强关联，intensity layer 随敌量 / 阶段叠加。

### 3.1 自适应分层（Intensity Layer）

| Layer | 内容 | 触发（假设 RTPC：`Combat_Intensity` 0–100） |
|---|---|---|
| L0 探索 | 低音 pad + 稀疏五声笛 | 搜刮 / 非战斗（Intensity < 20） |
| L1 接敌 | + 稳定节拍（鼓 / 脉冲） | 出现敌人（20–45） |
| L2 交火 | + 贝斯线条 + 主旋律 | 持续交火 / 弹幕（45–70） |
| L3 高压 | + 失谐铺底 + 高频琶音 | 大量敌 / 弹幕密集（70–90） |
| L4 Boss | 替换为 Boss 主题乐（分段） | Boss 战（≥90） |

### 3.2 BPM 与战斗节奏关联

| 场景 | BPM | 说明 |
|---|---|---|
| 基地 / 选装 | 96（自由律动） | 松弛，便于浏览 UI |
| 搜刮探索 | 112 | 轻步伐感，暗示"还在安全线内" |
| 普通战斗 | 128 → 140 | 随 Intensity 微升，驱动弹幕手感 |
| 高压 / 弹幕墙 | 150–160 | 接近玩家反应极限阈值，制造紧张 |
| Boss 一阶段 | 144 | 稳定压迫 |
| Boss 二阶段（狂暴） | 168 + 切 3/4 拍 | 打破稳定感，听觉"失序"对应机制变化 |
| 撤离倒计时 | 渐慢至 100 | 故意抽离节拍，制造"能不能跑掉"的悬疑 |

> 实现上：BPM 用音乐中间件 tempo 系统驱动，与 RTPC `Combat_Intensity` 绑定做平滑 crossfade；阶段切换用节拍对齐的 transition（避免破拍）。

## 4. 音频事件清单（草案，供工程 / QA 对齐）

事件命名：`域_类别_动作[_变体]`。下表为最小可用集（MVP），后续按实装扩展。

| 事件 ID | 触发时机 | 类型 | 备注 / 参数 |
|---|---|---|---|
| `SFX_BATTLE_FIRE` | 机体开火 | OneShot | 参数：`WeaponType`(light/heavy) |
| `SFX_BATTLE_HIT` | 命中敌人 | OneShot | 参数：`TargetSize`(s/m/l/boss) |
| `SFX_BATTLE_EXPLODE` | 敌/物体爆炸 | OneShot | 参数：`Scale`(0–1) |
| `SFX_PLAYER_HURT` | 玩家受击 | OneShot | 参数：`HP_Ratio`(0–1) 控制失真度 |
| `SFX_ROGUE_GET` | 随机强化获得 | Sequence | 参数：`Rarity`(common/rare/legend) |
| `SFX_MERGE_OK` | 合成成功 | Sequence | 双段：咬合 + 确认 |
| `SFX_MERGE_FAIL` | 合成失败（如有） | OneShot | 下沉闷响 |
| `SFX_EXTRACT_WIN` | 撤离成功 | Sequence | 主题解决版 |
| `SFX_EXTRACT_LOSE` | 撤离失败 | Sequence | 截断悬置版 |
| `UI_CLICK` / `UI_CANCEL` / `UI_SCROLL` | UI 操作 | OneShot | 高频段 |
| `MU_STATE_SET` | 设置音乐状态 | State | 参数：`Area`(base/map/boss) |
| `MU_INTENSITY` | 战斗强度 RTPC | GameParam | 0–100，驱动分层 |
| `MU_BPM_SET` | BPM 控制 | GameParam | 96–168 |
| `AMB_MAP` / `AMB_BASE` | 环境声 | Loop | 地图/基地环境垫 |
| `ALERT_EXTRACT` | 撤离窗口开启预警 | Sequence | 倒计时紧张铺垫音 |

## 5. 实现策略（推荐与理由）

> 假设：引擎决策尚未锁定，以下按"PC/Steam 卡通渲染、需动态音乐 + 大量 OneShot + 状态机"的典型需求评估。最终以工程引擎决策为准对齐。

| 方案 | 适合度 | 理由 | 风险 |
|---|---|---|---|
| **Wwise（推荐）** | ★★★★★ | 强大的动态音乐（Music Switch/Stinger）、RTPC 分层、事件量管理、对 Unity/Unreal 集成成熟；最契合本作"自适应音乐 + intensity layer + 海量音效"需求 | 授权成本（PC 小规模可走免费档）；学习曲线 |
| **FMOD** | ★★★★☆ | 动态音乐与参数系统同样强，Studio 可视化好；可作为 Wwise 平替 | 与 Wwise 二选一，避免双中间件 |
| **Unity Audio** | ★★☆☆☆ | 零成本、上手快；但大规模动态分层/状态机需自研，维护成本高 | 单局音效量大时易成瓶颈，不推荐主选 |
| **Godot 内置** | ★★☆☆☆ | 若工程选 Godot 则可用，但动态音乐系统需较多手写 | 中间件生态弱于前两者 |

**推荐结论**：**首选 Wwise**（若工程选 Unity 或 Unreal）。理由：本作核心卖点是"战斗节奏 + 风险博弈的声音化"，Wwise 的 Music Transition / RTPC / State 能最低成本实现第 3 节的动态分层与 BPM 关联；事件 ID 草案已按 Wwise 习惯命名，可直接落地。

**对工程的假设（需对齐）**：
- 假设引擎为 **Unity 或 Unreal**（Wwise 集成最成熟）。
- 假设需要 **Wwise 免费授权档**（PC 营收阈值内）；超阈值再评估商业授权。
- 若工程最终选 **Godot**，则回退到 FMOD（Godot 有官方 FMOD 插件）或自研轻量动态音乐系统。

## 6. 与「战斗节奏」强关联的设计原则

1. **音效即 HUD**：所有核心战斗音效对齐 16 分音符网格，玩家可"听节奏"判断弹幕密度与换弹窗口，降低视觉负荷、强化心流。
2. **强度可听化**：`Combat_Intensity` 同时驱动音乐分层与混音（高压时压缩人声/垫底、提升打击瞬态），让"危险"直接作用于耳朵。
3. **风险博弈的声音签名**：
   - **撤离前紧张铺垫**：撤离窗口开启时，用 `ALERT_EXTRACT` 做"心跳式"低频脉冲 + 音乐渐慢（BPM 抽离），把"能不能跑掉"变成听觉悬念。
   - **撤离失败刻意不完整**：截断终止式 + 低频下沉，制造"东西没了"的失落，强化搜打撤的"损失痛感"。
   - **撤离成功给解决感**：五声终止式 + 暖垫，奖励"冒险落袋"。
4. **正反反馈不对称**：正反馈（命中/强化/合成）短促明亮、即时；负反馈（受击/失败）带失真与下沉，形成"爽—痛"对比，放大肉鸽/搜打撤的情绪波动。
5. **Boss 阶段的听觉失序**：二阶段切 3/4 拍、加失谐，让"机制变化"在听感上先一步被感知，减少"突然变难"的突兀。
