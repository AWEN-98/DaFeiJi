# 用户反馈渠道与闭环（Feedback Channels）

> 角色：release-ops-lead ｜ 目标：建立"收集→分类→响应→落地"闭环，反哺设计与数值。
> 协作：quality-lead（质量/崩溃）、design-strategist（设计/数值）。

## 1. 渠道矩阵

| 渠道 | 类型 | 最佳用途 | 响应时效 | 负责人 |
|---|---|---|---|---|
| Discord | 社区/实时 | 讨论、建议、情绪、共创 | 当日(工作日) | community-ops |
| Steam 评测与讨论区 | 公开/声誉 | 口碑、差评根因、竞品对比 | 48h 内回应差评 | release-ops |
| 游戏内反馈入口 | 结构化/场景化 | 局内崩溃、平衡痛点、具体建议 | 自动入库 T+0 | 技术+quality-lead |
| 结构化问卷 | 定量/分段 | 退出问卷、Next Fest 调研、满意度(NPS) | 批次分析 | release-ops |

**渠道分工要点**
- 游戏内入口放"撤离成功页"与"阵亡页"各一个轻量按钮（1 题+可选截图），降低填写摩擦。
- Discord 设"建议/bug/平衡"三个频道 + 投票机器人，便于聚合热门。
- Steam 差评需标记"可复现/配置/平衡/其他"，进入同一分类表。

## 2. 工作流：收集 → 分类 → 响应 → 落地

| 阶段 | 动作 | 工具 | 角色 | 产出 |
|---|---|---|---|---|
| 收集 | 多源汇入统一反馈池 | Discord 机器人 + 表单 + 崩溃上报 | community-ops / 技术 | 原始反馈条目 |
| 分类 | 打标签：bug/平衡/内容/体验/IP/其他 + 严重度 + 来源 | 反馈表(表格/看板) | quality-lead | 已分类条目 |
| 响应 | 公开确认/ roadmap 引用/ 私信致谢 | Discord/ Steam 公告 | release-ops | 响应记录 |
| 落地 | 转 issue → 排期 → 验证 → 关单 | 任务系统/ changelog | design-strategist + 技术 | 已解决条目 |

**严重度分级（SLA）**
| 等级 | 定义 | 响应 | 解决 |
|---|---|---|---|
| P0 | 崩溃/数据丢失/无法撤离 | 24h | 热修 |
| P1 | 严重平衡破坏/卡关 | 48h | 下个补丁 |
| P2 | 体验痛点/建议 | 周更汇总 | 路线图 |
| P3 | 锦上添花 | 归档 | 待定 |

## 3. 反馈反哺设计与数值（闭环）

> 与 quality-lead、design-strategist 共建"数据—反馈—调参"回路。

| 信号来源 | 反哺对象 | 动作 | 频率 |
|---|---|---|---|
| 局内死亡原因分布 | 数值/难度曲线 | 调整弹幕密度、Boss 血量、强化权重 | 每补丁 |
| 撤回率(进入未撤离) | 风险博弈平衡 | 校准带入损失比、撤离收益 | 每补丁 |
| 合成/强化选择热力 | 组合深度 | 增补冷门组合、削弱超模 | 双周 |
| Discord 高票建议 | 设计路线图 | 纳入里程碑 backlog | 月度 |
| 问卷 NPS/留存 | 元进度节奏 | 调成长反馈强度 | 月度 |

**闭环原则**
- 每条 P0/P1 反馈必须可追到 changelog 条目（发布清单联动）。
- 平衡改动先在 Alpha/测试分支灰度，再随补丁全量。
- 月度发布"开发者回顾"：公开"你们的声音→我们改了什么"，强化社区信任。
